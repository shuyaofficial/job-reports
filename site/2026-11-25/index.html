くわしく読む

生の git diff を LLM に渡すと、もっともらしいが事実と異なる変更履歴が生成されてしまう、という問題を扱った記事です。diff には「何が変わったか」は現れても「なぜ変わったか」は含まれないため、本当の意図を取り出すには紐付いた Issue の参照と、「その変更がなければ結果はどう変わったか」を検証する反事実的な評価(counterfactual evals)が必要だと論じています。実務では、AI によるリリースノート自動生成に Issue やPRの文脈を組み込み、生成結果を反事実評価で検証する設計が有効だと示唆しています。
